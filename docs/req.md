## 一、项目目标

实现一个网页工具，用户上传一个或多个 DeepSeek 导出的 JSON 聊天记录文件后，工具在浏览器本地解析、去重、缓存并展示。界面布局和交互高度还原 DeepSeek 网页版聊天界面：

- 左侧：会话 session 列表，显示会话标题、更新时间、消息数量，可按时间倒序排列，可搜索过滤。
- 右侧：选中会话后的聊天详情，按消息顺序展示用户和助手消息，支持 Markdown、代码块、时间等信息。
- 底部：保留类似 DeepSeek 的输入框外观，但处于禁用/占位状态，提示“预览模式，暂不支持发送消息”。

视觉目标是在布局、间距、配色、圆角、字体层级、侧边栏和消息气泡样式上与 DeepSeek 网页版高度一致。不要复制官方 Logo、商标或受版权图片，可用中性文字标识或内联 SVG 图标替代。

## 二、硬性约束

1. 纯前端，无后端，无数据库服务。
2. 所有解析、去重、缓存、搜索都在浏览器本地完成。
3. 不得使用 fetch、XHR、WebSocket、第三方统计脚本等上传任何聊天数据。
4. 运行时不得依赖外部 CDN；字体、图标、样式、脚本都应本地打包或内联。断网后仍可使用。
5. 使用 IndexedDB 持久化会话数据；刷新页面后数据仍在；用户清除浏览器缓存/站点数据后数据消失。
6. 不使用账号、登录、云同步。
7. 暂不实现发送消息、接入模型 API、导出、树状图、云备份等功能。
8. 渲染 Markdown 时必须做 XSS 防护，不能直接 innerHTML 未净化内容。
9. 不要询问我数据格式。请实现格式适配层，兼容常见 DeepSeek 导出 JSON 结构，并在 README 中说明假设。

## 三、技术栈要求

推荐使用：

- Vite + Vue3 + TypeScript
- 原生 CSS / CSS Modules / TailwindCSS
- IndexedDB 封装可用 idb，也可手写
- Markdown 渲染用 marked + DOMPurify
- 代码高亮可选，非必需
- 图标使用内联 SVG

如果你认为单 HTML 文件更合适，也可以，但必须完整可运行，并说明取舍。优先保证可维护性和完整功能。

## 四、功能需求

### 1. 多 JSON 文件导入

- 支持点击选择文件和拖拽上传。
- 支持一次上传多个 JSON 文件。
- 支持重复上传同一个文件或包含重复会话的文件。
- 导入时显示进度或至少显示导入结果。
- 导入完成后提示：扫描文件数、识别会话数、新增会话数、跳过重复数、失败文件及原因。

### 2. JSON 格式适配

请实现一个适配层，尽量兼容以下形态：

- 顶层是会话数组；
- 顶层是 `{ conversations: [...] }`；
- 顶层是 `{ data: [...] }`、`{ chats: [...] }`；
- 单个会话对象也可能直接上传；
- 消息字段可能是 `messages`、`message_list`、`chat_messages`；
- 内容字段可能是 `content`、`text`、`message`；
- 角色字段可能是 `role`、`author`、`sender`，值可能是 `user` / `assistant` / `human` / `ai` 等；
- 时间字段可能是 `created_at`、`updated_at`、`create_time`、`timestamp`。

请把适配后的统一内部结构定义为：

```ts
type ChatMessage = {
  id: string;
  role: 'user' | 'assistant' | 'system' | 'unknown';
  content: string;
  createdAt?: string;
  raw?: unknown;
};

type Conversation = {
  id: string;
  title: string;
  createdAt?: string;
  updatedAt?: string;
  model?: string;
  messages: ChatMessage[];
  sourceFile?: string;
  fingerprint: string;
};
```

如果字段缺失，使用合理默认值，不要因为单个字段缺失导致整个文件导入失败。

### 3. 自动去重

必须实现会话级和消息级去重：

- 会话优先使用原始 `id` 作为唯一键；
- 如果没有稳定 id，则使用规范化指纹：标题 + 消息角色/内容/时间排序后的哈希；
- 消息优先使用原始消息 id；
- 没有消息 id 时，用 `role + content + createdAt` 的哈希作为消息指纹；
- 多个文件中出现同一会话时，合并消息并去重，保留更新时间较新的元数据；
- 同一文件重复上传时，不应产生重复会话；
- 去重后要在导入结果中显示跳过数量。

### 4. 本地缓存

- 使用 IndexedDB 存储会话列表和消息。
- 应用启动时自动读取 IndexedDB 并恢复界面。
- 导入成功后自动写入 IndexedDB。
- 提供“清空本地数据”按钮，点击后删除 IndexedDB 中的聊天数据并刷新列表。
- 可选：支持删除单个会话。
- 不要把大量聊天内容塞进 localStorage；localStorage 只可存主题等小配置。

### 5. 左侧会话列表

- 按 `updatedAt` 倒序排列；没有时间则按导入顺序。
- 显示会话标题、最后更新时间、消息数量。
- 当前选中会话高亮。
- 支持折叠/展开侧边栏；移动端用抽屉式侧边栏。
- 支持按标题过滤。
- 空状态显示引导上传。

### 6. 右侧聊天详情

- 顶部显示会话标题、模型名（如有）、消息数、创建/更新时间。
- 消息按顺序展示，用户消息和助手消息样式区分。
- 支持 Markdown 渲染：标题、列表、表格、引用、链接、行内代码、代码块。
- 代码块显示语言标签和复制按钮。
- 长会话要保证基本性能，可做懒加载或分页，但不要过度设计。
- 底部保留输入框外观但禁用，占位提示“预览模式，暂不支持发送消息”。

### 7. 搜索

- 顶部或侧边栏提供搜索框。
- 搜索范围包括会话标题和所有消息内容。
- 大小写不敏感，支持中文。
- 输入时即时过滤左侧会话列表，并显示每个会话的匹配数量。
- 选中会话后，右侧显示匹配高亮；可提供“上一条/下一条匹配”或至少高亮所有匹配片段。
- 搜索结果点击后能定位到对应消息附近。
- 搜索完全在本地内存/IndexedDB 数据上完成，不发起网络请求。

### 8. 错误与边界处理

- 非 JSON 文件、损坏 JSON、无法识别结构时给出明确提示，不影响其他文件导入。
- 空会话、空消息、超长消息、缺少标题要有兜底展示。
- 大文件导入时避免界面完全卡死，可使用异步解析和分批写入 IndexedDB。
- Markdown 渲染必须防 XSS。
- 不要因为单个文件失败而中断整个导入流程。

## 五、非目标

本期不要实现：

- 发送消息或调用任何模型 API；
- 登录、云同步、多人协作；
- 导出 Markdown/JSON/HTML；
- 树状分支视图；
- 复杂统计图表；
- 后端服务。

但代码结构要为后续增强留出空间，例如数据层、适配层、搜索层、UI 层分离。

## 六、验收标准

请确保满足以下验收项：

1. 上传一个 DeepSeek 导出 JSON 后，左侧出现会话列表，右侧可查看聊天详情。
2. 一次上传多个 JSON，重复会话只显示一次，并提示跳过重复数量。
3. 刷新页面后数据仍在；清除站点数据后数据消失。
4. 断网后页面仍可打开并浏览已导入数据。
5. 浏览器 Network 面板中没有任何上传聊天数据的请求。
6. 搜索标题和消息内容都能命中，并能定位/高亮。
7. Markdown 和代码块正常显示，恶意 HTML 被净化。
8. 非 JSON 或结构异常文件有错误提示，且不影响其他文件。
9. 界面布局高度接近 DeepSeek 网页版：左侧会话栏、右侧消息区、底部输入框占位、消息气泡样式一致。
10. 不出现官方 Logo 或受版权图片。
